## Items

### 1. Per-task resource capture — implemented
Promotes the existing `task_complete`/`task_failed` jsonl events (duration)
into the metadata DB and adds peak RSS, for all executors. **Design pass
done 2026-07-31 — [resource_capture.md](../designs/resource_capture.md).**
Decided there: last-execution `wall_s`/`cpu_s`/`max_rss_bytes`/`rss_method`
columns on `task` in `remake.db` (the append-only per-execution `stats.db`
of discussion.md stays 0.10.x), measured in `run_task` — the one chokepoint
all executors share — by a `/proc` sampler thread, since `ru_maxrss` is a
process high-water mark and would mis-attribute a pooled worker's earlier
peak. Output bytes are *not* duplicated here: they are `output_stat`
(item 5). Known caveats from the 2026-09-24 review: child-process RSS
under-reporting (M18), `set-state --pending` deleting the figures (L15), a
sampler stop race (L16).

### 2. Change-detection correctness
From the [2026-09-24 review](../code_reviews/2026-09-24_review.md). Every
fix normalises *both* the stored and the current side, and is tested for "no
mass rerun on upgrade".

- **H2** — strip the `@rule(...)` decorator from run code.
- **H3** — path-derived task-to-task dependencies replacing the
  shared-matrix element-wise assumption (design: review Appendix A; shared
  with SLURM's `_elementwise()`). The failure-skip part may ship in 0.8.4.
- **H4, H5** — canonical, order-insensitive, Python-version-independent
  rendering of `uses` values and io specs (sets, dict order, `ast.dump`).
- **M1–M4** — scope-analysis fidelity (instances, name-shadowing,
  project-local modules, helpers defined below rules) and lossless rendering
  of sourceless callables and numpy/pandas values (with a user hash hook).
- **M8** — resolved-path digest so shrinking fan-ins rerun.
- **M19** — canonical task keys (exact scalar types), with a key-migration
  story.

### 3. Schema version
`PRAGMA user_version`, set on create and bumped by each migration. Required
by the 1.0 contract ("where not, remake refuses to run and prints the upgrade
step" — impossible without detecting the writer's version). Pairs with the
0.8.4 atomic-migration fix (review M5/M6).

### 4. Output validation (`Ensure`) + checksum capture
`ensure`-style validation on the token ABC — non-empty / size / checksum
checked at completion, not just existence. **Checksum split (decided
2026-07-14, MM):** 0.9.0 *records* output checksums — a `checksum` column
riding the same early `output_stat` migration as item 5, computed opt-in
(`checksum_outputs=True` per rule/global, `Ensure(checksum=True)` per output;
never default — hashing re-reads every byte) at the post-success hook in the
task process (page-cache hot; SLURM carries it via sidecar/ingest), sha256
for provenance-interop, per-file in `Dir` manifests under the same knob.
Everything that *reads* a checksum comes later: `verify`-style commands
(0.10.x), RO-Crate (after 1.0 — which is why capture can't wait), and any
checksum-based staleness, which is a NEW RERUN TRIGGER and gets its own
design pass. Open: the validator API itself; keep it small.

### 5. Directory outputs (`Dir` token)
Added to scope 2026-07-14 (MM); design pass done, decisions settled in
[dir_outputs.md](../designs/dir_outputs.md) (manifest-based completion,
never delete user files, stale-file attribution, `output_stat` aggregates).
Dovetails with 1 (disk usage is a resource) and 4 (the manifest is a
validation primitive); shares 4's early schema addition.

### 6. Fail fast on missing external inputs + per-remakefile hint
Added 2026-07-14 (MM). Before executing, if a task about to run has missing
inputs that no rule produces (`lint`'s `external` class), stop with a list
instead of N FileNotFoundError task failures.
`Remake(config={'external_inputs_hint': ...})` appends a pipeline-specific
nudge to that error — the examples point at `make_example_data.py`; a
download/process project can say "run download.py first" (messaging-only
slice of the parked remakefile-deps feature). Deliberately NOT an
interactive prompt and core knows nothing about examples. Scale note: only
stat inputs of tasks actually about to run.

### 7. Configuration: profiles + config-file cascade
One design covering both (merged 2026-09-24 — the config file format becomes
a frozen surface, so design it once):

- **Named profiles**, with a shipped `jasmin` profile (partition/qos/time/
  mem defaults; *not* `account`, which is per-user — require or validate
  it) — the migration-facing piece, replacing the hardcoded
  `DEFAULT_SLURM_CONFIG`.
- **Three-level cascade** — `~/.remake/config.yaml` →
  `<project>/.remake/config.yaml` → remakefile → per-rule (discussion.md
  "configuration"), with defined deep-merge semantics incl. removing an
  inherited key.
- **CLI selection/overrides** — `--profile`, possibly `--config k=v`.
- **Guards:** config never becomes a rerun trigger by accident (executor
  and SLURM resources must not stale tasks); the *effective* merged config
  is recorded per run (reproducibility; feeds 0.10 provenance).

### 8. Static DAG export
`remake dag [--rules|--tasks] -o graph.dot` — the rule-level graph remake
already builds, as Graphviz. Near-free; onboarding/debugging aid.

### 9. `remake run-all`
Added 2026-07-14 (MM); discovery + run of all remakefiles in a directory,
*without* ordering (the dependency half is parked —
[remakefile_deps.md](../designs/remakefile_deps.md)). Small: AST-scan
discovery (never import), sorted-filename order, continue past failures
with a summary. Makes "run all the examples" one command. Keep only if it
stays this small.

- **Single-file HTML run report** (`remake report`) — additive; after 1.0
  (roadmap "After 1.0" item 2). Resource capture keeps accumulating the
